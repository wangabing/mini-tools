# 中国可入驻电商平台 Top 20 与成本规则调研

> 版本：1.0  
> 调研日期：2026-10-03  
> 用途：为“电商利润计算器”后续接入中国电商平台、类目费率和结算规则提供产品与数据建模依据。

## 1. 结论摘要

中国没有一个官方榜单能够同时对货架电商、内容电商、二手交易、B2B 和即时零售给出统一的前二十名。GMV、月活、订单量和商家数量的排名口径不同，部分平台也不公开完整数据。

本文所称 Top 20 是“平台规模和用户影响力 + 商家可入驻性 + 利润计算器集成价值”的优先级名单，不代表精确市场份额排名。所有平台均核验到仍可访问的官方商家入口、招商入口或卖家后台；受邀制平台也被保留，但会明确标记。

核心工程结论：

1. 平台成本不能只建模为一个佣金百分比。
2. 保证金通常可退，属于资金占用，不应直接作为订单费用。
3. 技术服务费、支付费、达人佣金可能采用不同计费基数，不能简单相加后统一乘以售价。
4. 平台券、商家券、退款、运费和税费是否进入计费基数，必须逐条记录。
5. 即时零售和特卖平台大量采用门店、城市或合同费率，不能提供未经验证的公开默认值。
6. 只有存在可复核官方来源、适用类目和生效日期时，计算器才能自动填入费率；否则只能让用户手工输入。

## 3. 通用成本模型

### 3.1 收入拆分

```text
买家应付 = 商品金额 + 买家支付运费 - 商家优惠 - 平台优惠

卖家结算收入 = 买家实付
             + 平台承担且补给商家的优惠
             - 退款金额
             - 平台代扣税费
             - 平台代扣的各类服务费
```

平台优惠不能默认等同于商家让利。计算器至少要区分：

- 商家券、店铺满减和商家承担的平台活动补贴；
- 平台全额承担且实际补给商家的优惠；
- 平台与商家按比例共同承担的优惠；
- 先收后返、跨期返还或需要完成活动条件才返还的补贴。

### 3.2 平台费用拆分

```text
订单平台成本 = 比例技术服务费
             + 固定订单服务费
             + 支付渠道费
             + 达人/分销佣金
             + 订单归因广告成本
             + 平台履约或仓配费
             + 运费险及售后服务费
             + 退款后不退还的费用

期间平台成本 = 年费/会员费/软件套餐费
             + 固定平台使用费
             + 非订单归因广告费
             + 仓储和其他周期费用
```

期间费用应按预计订单量或销售额摊销，不能直接全部计入一笔订单。

### 3.3 保证金处理

保证金通常是可退资金，不属于会计意义上的订单费用。计算器应提供两种视图：

- 默认视图：不进入单笔利润，只显示“开店资金占用”。
- 资金成本视图：按用户设定的资金年化成本进行摊销。

```text
保证金资金成本/单 = 保证金金额 × 年化资金成本率 × 占用天数 / 365 / 预计订单数
```

罚款、赔付或保证金扣除不能作为正常订单成本预设，只能作为风险情景输入。

### 3.4 费率计费基数

每条费率必须独立保存计费基数，常见基数包括：

- 商品成交金额；
- 买家实付金额；
- 含运费订单金额；
- 不含运费订单金额；
- 扣除平台补贴前或后的金额；
- 退款后的净结算金额；
- 商家与达人约定的佣金基数；
- 阶梯中的月累计成交额或订单数。

因此不能使用“所有费率相加后统一乘以订单收入”的简化模型覆盖全部平台。

## 4. 各平台成本计算规则

### 4.1 淘宝

主要成本：消费者保障保证金、基础软件服务费、类目或专项服务费、支付相关费用、淘宝客佣金、推广费、运费险和物流。

建议公式：

```text
淘宝订单成本 = 各自计费基数 × 对应软件服务费率
             + 淘宝客计佣基数 × 淘宝客佣金率
             + 支付/保险/物流固定费用
             + 订单归因推广成本
```

集成注意：

- 店铺主体、类目、活动和商家身份可能改变费率或减免规则。
- 淘宝基础软件服务费政策曾调整，不能把历史公开比例永久写死。
- 淘宝客佣金和直通车/万相台广告是可选成本，应与平台技术服务费分开。
- 退款时各费用是否退回需要单独配置。

官方入口：[淘宝卖家中心](https://seller.taobao.com/)；[淘宝规则中心](https://rulechannel.taobao.com/)。

### 4.2 天猫

主要成本：保证金、基础软件服务费、类目软件服务费、可能存在的固定或周期服务费、淘宝客/内容佣金、推广、保险和物流。

建议公式：

```text
天猫订单成本 = 基础服务费计费基数 × 基础费率
             + 类目服务费计费基数 × 类目费率
             + 内容/分销计佣基数 × 佣金率
             + 支付、保险、物流及广告成本
```

集成注意：

- 旗舰店、专卖店、专营店及类目资质不同，保证金和费率不能共用一个预设。
- 天猫历史上存在年费及返还机制，政策已经多次调整；数据模型要保留周期费，但是否启用必须以当前规则为准。
- 类目扣点、基础服务费和营销佣金可能同时存在，不能互相替代。

官方入口：[天猫招商](https://zhaoshang.tmall.com/)；[天猫规则中心](https://rulesale.taobao.com/)。

### 4.3 京东开放平台

主要成本：保证金、平台使用费或周期费、类目技术服务费、支付费用、京东联盟佣金、京准通广告、京东物流及售后服务。

建议公式：

```text
京东订单成本 = 订单计费基数 × 类目技术服务费率
             + 联盟计佣基数 × 联盟佣金率
             + 平台固定费摊销
             + 支付、广告、仓配和售后成本
```

集成注意：

- POP 店铺模式、店铺类型、类目和履约方案决定实际费用。
- 京东物流费用需要按重量、体积、区域、仓配模式单独建模，不能当成统一固定运费。
- 平台使用费如按月或年收取，应按预测订单量摊销。

官方入口：[京东招商](https://zhaoshang.jd.com/)；[京东开放平台规则](https://rule.jd.com/)。

### 4.4 拼多多

主要成本：店铺保证金、支付或技术服务费、特殊类目或业务服务费、多多进宝佣金、推广费、物流、运费险和售后损失。

建议公式：

```text
拼多多订单成本 = 支付计费基数 × 支付服务费率
               + 类目/业务计费基数 × 专项费率
               + 多多进宝计佣基数 × 佣金率
               + 推广、保险、物流和售后成本
```

集成注意：

- “平台佣金为零”不能作为所有类目和所有时期的永久规则。
- 百亿补贴、限时活动等可能包含商家让利、补贴或保证金要求，应作为活动规则层处理。
- 退款、先用后付、运费险和售后补偿需要单独记录。

官方入口：[拼多多商家后台](https://mms.pinduoduo.com/)；帮助中心位于商家后台登录后。

### 4.5 抖音电商

主要成本：商家保证金、类目技术服务费、支付相关费用、精选联盟或达人佣金、巨量千川广告、运费险、物流和售后。

建议公式：

```text
抖音订单成本 = 结算计费基数 × 类目技术服务费率
             + 达人计佣基数 × 达人佣金率
             + 支付、保险、物流和售后费用
             + 订单归因千川广告成本
```

集成注意：

- 商城自营订单和达人带货订单的成本结构不同。
- 达人佣金、机构服务费和平台技术服务费必须分栏，不能只显示“平台费”。
- 新商家、产业带或活动减免要保存开始和结束日期。
- 广告应优先接受单笔归因成本，也可由总消耗和成交订单反推。

官方入口：[抖店](https://fxg.jinritemai.com/)；[抖音电商学习中心](https://school.jinritemai.com/doudian/web/home)。

### 4.6 快手电商

主要成本：商家保证金、类目技术服务费、支付相关费用、快分销佣金、磁力金牛推广、运费险、物流和售后。

建议公式：

```text
快手订单成本 = 订单计费基数 × 类目技术服务费率
             + 分销计佣基数 × 快分销佣金率
             + 支付、保险、物流和售后费用
             + 订单归因推广成本
```

集成注意：

- 自建直播、达人分销和商城自然成交应使用不同的预设组合。
- 商家承担的直播间优惠和平台补贴必须分开。
- 费率减免和类目准入规则要按有效期版本化。

官方入口：[快手电商商家工作台](https://s.kwaixiaodian.com/)；[快手电商学习中心](https://edu.kwaixiaodian.com/)。

### 4.7 微信小店

主要成本：保证金、类目技术服务费、可能单列的支付服务费、视频号达人佣金、广告互选或投流、物流和售后。

建议公式：

```text
微信小店订单成本 = 平台计费基数 × 类目技术服务费率
                 + 达人计佣基数 × 达人佣金率
                 + 经账单确认的支付费用
                 + 广告、物流和售后成本
```

集成注意：

- 不能在未确认账单结构时同时重复计入技术服务费和微信支付费。
- 橱窗带货、店铺自营、达人分销的佣金结构不同。
- 类目、主体类型及信用情况会影响保证金。

官方入口：[微信小店](https://channels.weixin.qq.com/shop)；[微信小店规则](https://channels.weixin.qq.com/shop/rules)。

### 4.8 小红书电商

主要成本：店铺保证金、技术服务费、支付渠道费、买手或达人佣金、薯条/聚光推广、物流、运费险和售后。

建议公式：

```text
小红书订单成本 = 平台计费基数 × 技术服务费率
               + 支付计费基数 × 支付渠道费率
               + 买手计佣基数 × 买手佣金率
               + 推广、物流、保险和售后成本
```

集成注意：

- 店铺自营与买手带货必须区分。
- 支付渠道费和平台技术服务费是不同费用项。
- 不同类目、商家类型和活动期的费率应独立版本化。

官方入口：[小红书商家管理平台](https://ark.xiaohongshu.com/)；[小红书电商学习中心](https://school.xiaohongshu.com/)。

### 4.9 闲鱼

主要成本：基础软件服务费、对高频或高额经营卖家的附加服务费、物流、验货/保障服务及售后损失。

建议使用阈值规则，而不是单一费率：

```text
当月费用 = Σ 基础交易费用
         + Σ 满足“月订单数/成交额阈值”后的经营性卖家费用
         + 物流、验货和保障费用
```

集成注意：

- 个人偶发出售与持续经营卖家的收费和合规属性不同。
- 阈值可能同时使用月成交笔数、月成交额、单笔封顶等条件。
- 计算器需要累计月订单状态，不能只看单笔订单。
- 数字、奢品、手机等服务可能包含独立验货或保障费用。

官方入口：[闲鱼网页版](https://www.goofish.com/)；具体收费规则以闲鱼 App 内规则中心和卖家账单为准。

### 4.10 1688

主要成本：诚信通或其他会员年费、买家保障保证金、交易服务费、分销佣金、数字营销、物流、赊账或金融服务成本。

建议公式：

```text
1688 订单成本 = 会员/软件年费摊销
              + 交易计费基数 × 交易服务费率
              + 分销计佣基数 × 分销佣金率
              + 推广、物流和金融成本
```

集成注意：

- 批发订单需支持多件商品、阶梯单价和整单物流分摊。
- 会员费属于期间固定成本，不应表现为订单佣金。
- 账期和赊销需要加入资金占用成本。

官方入口：[1688 商家工作台](https://seller.1688.com/)；[1688 规则中心](https://rule.1688.com/)。

### 4.11 唯品会

主要成本：保证金、合同扣点或结算折扣、仓储配送、退货处理、营销活动和可能存在的固定服务费。

建议使用合同驱动模型：

```text
唯品会订单利润 = 合同结算收入
               - 商品成本
               - 仓配及退货成本
               - 合同约定的服务费和活动分摊
```

集成注意：

- 特卖联营、平台招商和不同履约模式不能共用公开默认费率。
- 退货率对服饰等类目影响很大，应支持按结算周期估算。
- 在获得商家合同前，只提供自定义字段，不自动填费率。

官方入口：[唯品会供应商平台](https://vis.vip.com/)。

### 4.12 得物

主要成本：保证金、技术服务费、运营服务费、支付费、鉴别查验费、包装或仓储费、物流及售后费用。

建议使用“类目 + 商品价格档位 + 履约模式”规则：

```text
得物订单成本 = 技术服务费
             + 运营/支付服务费
             + 鉴别查验固定费或阶梯费
             + 平台履约、包装和物流费
             + 售后损失
```

集成注意：

- 鉴别费可能是固定额、阶梯额或与品类相关，不能换算成一个统一比例。
- 个人卖家和品牌/企业商家的收费项可能不同。
- 需要支持寄售、现货和其他履约方式。

官方入口：[得物商家后台](https://merchant.dewu.com/)。

### 4.13 美团闪购

主要成本：保证金、平台服务费或佣金、支付费、平台配送费、商家自配送成本、活动补贴、推广和售后。

建议公式：

```text
闪购订单成本 = 订单计费基数 × 合同服务费率
             + 平台配送费或商家自配送成本
             + 商家承担的活动优惠
             + 支付、推广、包装和售后成本
```

集成注意：

- 费率受城市、门店、品类、配送方案和合同影响。
- 配送费需要区分买家支付、平台承担和商家承担部分。
- 只允许用户录入合同费率，公开页面不提供统一默认值。

官方入口：[美团规则中心](https://rules-center.meituan.com/)；商家入驻以美团商家端为准。

### 4.14 京东秒送/京东到家

主要成本：保证金或合同资金要求、平台服务费、支付费、即时配送、营销活动、广告和售后。

建议公式：

```text
京东到家订单成本 = 订单计费基数 × 合同费率
                 + 平台履约或自配送成本
                 + 商家承担优惠
                 + 支付、推广、包装和售后成本
```

集成注意：

- 与京东传统 POP 店铺是不同成本模型。
- 门店、城市和即时配送距离需要成为规则维度。
- 费率以门店合同和后台账单为准。

官方入口：[京东到家商家中心](https://store.jddj.com/)。

### 4.15 饿了么零售

主要成本：平台服务费、支付费、蜂鸟配送或自配送、活动补贴、竞价推广、包装和售后。

建议公式：

```text
饿了么订单成本 = 订单计费基数 × 合同服务费率
               + 平台配送费或自配送成本
               + 商家活动承担金额
               + 支付、推广、包装和售后成本
```

集成注意：

- 费率和配送成本依赖城市、距离、时段、品类和合同。
- 满减活动必须拆分平台承担与商家承担。
- 应优先允许导入账单参数，不提供全国统一预设。

官方入口：[饿了么开店](https://kaidian.ele.me/)。

### 4.16 苏宁易购开放平台

主要成本：保证金、平台使用费、类目技术服务费、支付、推广、物流仓储和售后。

建议公式：

```text
苏宁订单成本 = 订单计费基数 × 类目服务费率
             + 固定平台费用摊销
             + 支付、推广、仓配和售后成本
```

集成注意：

- 当前招商范围、类目和费率应在接入前由商家后台再次确认。
- 在没有公开且近期复核的类目表时，只提供自定义费率。

官方入口：[苏宁开放平台](https://sop.suning.com/)。

### 4.17 当当开放平台

主要成本：保证金、平台使用费、类目佣金或技术服务费、营销、物流和退换货。

建议公式：

```text
当当订单成本 = 订单计费基数 × 类目费率
             + 固定平台费用摊销
             + 推广、物流和退换货成本
```

集成注意：

- 图书与百货的折扣、结算和退货规则差异明显。
- 开放平台可访问不代表全部类目持续开放招商，应以申请结果为准。

官方入口：[当当开放平台](https://open.dangdang.com/)。

### 4.18 百度爱采购

主要成本：会员或服务商套餐费、企业认证、线索获取、推广、可能的交易服务和销售履约成本。

建议使用线索电商模型：

```text
获客成本 = 会员及固定服务费摊销 + 推广消耗 / 有效线索数
成交获客成本 = 获客成本 × 平均成交所需线索数
订单利润 = 成交收入 - 商品及履约成本 - 成交获客成本 - 交易相关费用
```

集成注意：

- 爱采购同时包含线索和交易场景，不能强行套用商城佣金模型。
- 关键输入应是线索成本、转化率和客单价。
- 套餐和服务商报价以合同为准。

官方入口：[百度爱采购](https://aicaigou.baidu.com/)；[百度商家入驻](https://kaidian.baidu.com/mallplat/index.html)。

### 4.19 微店

主要成本：店铺或 SaaS 套餐费、支付服务费、平台场景服务费、分销佣金、推广、物流和售后。

建议公式：

```text
微店订单成本 = 套餐固定费摊销
             + 支付计费基数 × 支付费率
             + 平台场景计费基数 × 场景服务费率
             + 分销计佣基数 × 分销佣金率
             + 推广、物流和售后成本
```

集成注意：

- 自有私域成交和微店平台流量场景的费用不同。
- 不同店铺版本、担保交易和分销功能要分别建模。

官方入口：[微店商家平台](https://d.weidian.com/)。

### 4.20 孔夫子旧书网

主要成本：店铺等级或周期服务费、消费者保障资金、交易服务费、支付费、推广、包装物流和纠纷损失。

建议公式：

```text
孔网订单成本 = 店铺固定费摊销
             + 订单计费基数 × 交易服务费率
             + 支付、推广、包装、物流和售后成本
```

集成注意：

- 普通图书、古旧书和收藏品的价格、鉴定、包装与售后风险不同。
- 店铺等级和经营身份应成为预设维度。

官方入口：[孔夫子旧书网卖家中心](https://seller.kongfz.com/)。

## 5. 六类规则引擎

后续实现不需要为二十个平台分别写二十套公式。可以把规则归为六类：

| 规则类型 | 代表平台 | 引擎能力 |
| --- | --- | --- |
| 标准比例与固定费用 | 淘宝、天猫、京东、拼多多、苏宁、当当 | 多个费率、多个计费基数、固定费和封顶 |
| 内容与分销佣金 | 抖音、快手、微信小店、小红书、微店 | 平台费与达人/分销佣金分离 |
| 阈值与累计阶梯 | 闲鱼 | 按月订单数、成交额、单笔封顶切换规则 |
| 合同与结算价 | 唯品会、美团、京东到家、饿了么 | 用户输入合同费率，不提供公共默认值 |
| 会员与线索成本 | 1688、百度爱采购、微店、孔夫子 | 周期费用摊销、线索成本和转化率 |
| 鉴别与履约阶梯 | 得物 | 类目、价格档位、履约方式对应固定或阶梯费用 |

## 6. 建议数据结构

```ts
interface PlatformRuleSet {
  id: string;
  platformId: string;
  market: "CN";
  sellerType: string;
  shopType?: string;
  categoryId: string;
  fulfillmentMode?: string;
  version: string;
  effectiveFrom: string;
  effectiveTo?: string;
  reviewedAt: string;
  sourceUrl: string;
  sourceAccess: "public" | "login-required" | "contract-only";
  fees: FeeRule[];
  deposit?: DepositRule;
  notes: string[];
}

interface FeeRule {
  id: string;
  label: string;
  kind: "percentage" | "fixed" | "tiered" | "recurring" | "contract";
  basis:
    | "item-amount"
    | "buyer-paid"
    | "settlement-amount"
    | "commission-base"
    | "order"
    | "period";
  rate?: number;
  amount?: number;
  minimum?: number;
  maximum?: number;
  tiers?: FeeTier[];
  refundPolicy: "fully-reversed" | "partly-reversed" | "not-reversed" | "unknown";
  conditions: string[];
}

interface DepositRule {
  amount?: number;
  refundable: boolean;
  variesByCategory: boolean;
  variesByRisk: boolean;
}
```

还需要在订单输入中新增：

- 商家承担优惠、平台承担优惠和共同承担比例；
- 成交渠道：自然流量、广告、达人/分销；
- 达人或分销佣金；
- 技术服务费和支付费各自的计费基数；
- 退款金额及每项费用的退费状态；
- 固定平台费的摊销周期和预计订单数；
- 即时零售配送方式、距离和商家承担金额；
- 店铺主体、店铺类型、履约方式和活动类型。

## 7. 数据采集与上线门槛

### 7.1 可以自动填入的条件

平台预设只有同时满足以下条件才可上线：

- 来源是平台官方规则页、官方商家后台或商家合同；
- 明确适用平台、主体类型、店铺类型、类目和地区；
- 明确计费基数、费率/固定金额、最低/最高费用；
- 明确生效日期和最后复核日期；
- 明确退款时是否退还；
- 至少由两组人工样例账单验证计算结果。

### 7.2 不能自动填入的情况

- 只有培训机构、自媒体文章或招商代理报价；
- 官方页面要求登录，但尚未由真实商家后台核对；
- 费率来自私下合同且平台不存在统一标准；
- 缺少类目、店铺类型或有效期；
- 页面已失效或规则已被新版本替换。

此时计算器只显示平台专用字段，由用户手工填写，并标记“未提供公共默认费率”。

### 7.3 更新策略

- 第一批平台每 90 天复核一次，重大政策发布后立即复核。
- 规则文件保留历史版本，不能覆盖旧版本后失去订单复算能力。
- 每次更新记录来源 URL、抓取/人工复核时间和变更摘要。
- 合同平台不存储商家合同原文，只保存用户输入的计算参数。
- 费率来源不可访问时，不自动沿用为“当前费率”。

## 8. 下一步实施建议

第一阶段先接入淘宝、天猫、京东、拼多多、抖音和快手。这六个平台覆盖三种主要模型，且能验证多费率、多计费基数、达人佣金和退款处理。

第二阶段接入微信小店、小红书、闲鱼和 1688，补齐内容分销、月累计阈值和会员费摊销。

第三阶段再接入合同型、即时零售和垂直平台。唯品会、美团闪购、京东到家和饿了么只做“平台字段模板 + 用户合同参数”，不提供未经验证的默认费率。

首个实现变更应包含：

1. 将当前单一 `platformFeeRate` 升级为独立的多费用规则列表。
2. 增加每项费用的计费基数与退款策略。
3. 增加店铺类型、成交渠道和履约方式。
4. 实现固定周期费的订单摊销。
5. 实现达人/分销佣金与平台费分离。
6. 为闲鱼实现月累计阈值规则。
7. 保证旧的通用计算模式仍然可用，复杂字段继续放在高级设置中。

## 10. 风险说明

- 平台会频繁调整费率、减免、招商范围和类目规则，本文不是永久费率表。
- 登录后规则、合同和真实账单的优先级高于公开宣传页。
- 平台处罚、保证金扣除和异常赔付不应作为正常经营成本预设。
- 税费、开票、主体所得税和增值税需要单独的税务模型，不等同于平台服务费。
- “行业平均费率”只能作为手工参考，不能冒充平台官方预设。
