# 电商利润计算器产品需求文档

> 版本：1.3  
> 更新日期：2026-10-03  
> 产品名称：利衡电商利润计算器

## 1. 背景与目标

电商卖家通常能说清售价、货品成本和物流成本，但平台佣金、支付费、广告、退款损失和目标利润混在一起后，很难快速判断一笔订单是否值得继续销售。

产品目标是：让国内中小商家用少量熟悉的输入，在一个页面内得到专业、可解释、可用于定价和投放决策的结果；同时用平台对比页帮助新手先选对经营渠道。

## 2. 目标用户

- 在国内电商平台经营的个体户和小团队
- 通过短视频、直播、私域或货架渠道卖货的内容经营者
- 有本地门店、批发货源或产业带供给能力的经营者
- 不具备专业财务知识，但需要判断选品、定价和广告预算的新手卖家

## 3. 核心原则

1. 简单输入：默认表单不要求用户理解复杂会计术语。
2. 专业输出：结果必须覆盖利润、效率、定价和广告边界。
3. 口径透明：公式、费率来源和未覆盖规则可以被查看。
4. 允许修正：所有平台参考费率都可以手工覆盖。
5. 隐私优先：首版计算值只在浏览器内处理。
6. 联系可达：用户始终能找到公开邮箱，首版不提供在线留言。

## 4. 首版功能范围

### 4.1 默认输入

- 销售平台，默认“通用电商”
- 商品分类，默认“通用类目”
- 币种
- 商品售价
- 商品成本
- 物流或履约成本
- 单笔广告成本

### 4.2 高级输入

- 买家支付运费、订单折扣、包装和其他单笔成本
- 平台佣金、支付费率和固定支付费
- 税费预留、退款损失预留
- 目标利润率、预计月订单量

### 4.3 输出

- 单笔贡献利润、利润率、ROI 和月度利润
- 保本售价、目标利润售价
- 最大可承受广告成本、盈亏平衡 ROAS
- 收入、成本和利润贡献刻度
- 成本构成图及金额明细

### 4.4 平台与分类预设

- 支持通用模式，以及淘宝、天猫、京东、拼多多、抖音、快手、微信小店、小红书、闲鱼、1688、唯品会、得物、美团闪购、京东秒送/京东到家、饿了么零售、苏宁易购、当当、百度爱采购、微店和孔夫子旧书网。
- 分类列表随平台变化；没有分类规则时回退到平台通用预设。
- 非通用预设记录市场、官方来源、访问方式、复核日期、数据版本、未覆盖条件和核验提示。
- 无法从当前公开规则核验的费率保持为 0，但必须明确显示“待核对”，不得暗示免佣。
- 用户修改预设值后，页面必须显示“已手动调整”。

### 4.5 平台选择指南

- `/platforms` 对比全部 20 个国内平台的定位、门槛、适合人群、成本结构、优点和现实取舍。
- 用户可以按低门槛试水、内容带货、品牌经营、本地即时零售和批发/B2B 筛选。
- 用户最多保留三个候选平台并排比较，且可以随时移除。
- 近期内容只描述经营信号，并提供官方商家或活动入口；具体资格和权益以平台当前页面或合同为准。

### 4.6 联系方式

- `/contact` 显示联系邮箱 `mrwbz@sina.com`。
- 点击邮箱打开用户设备上的邮件应用，网站不接收或转发邮件内容。
- 联系页不包含在线留言输入框或发送按钮。
- 邮件链接不读取或附加计算器中的售价、成本、费率、平台选择和利润结果。

## 5. 非功能需求

- 支持 320px 至宽屏桌面，不产生横向滚动或文本遮挡。
- 所有交互支持键盘操作、可见焦点和语义标签。
- 支持减少动态效果的系统设置。
- 计算函数与 React 页面分离，内部不提前舍入。
- 提供独立元数据、Canonical、结构化数据、站点地图和 robots 配置。
- 未配置广告发布商时，不加载第三方广告请求，广告区域尺寸保持稳定。
- 始终使用 Next.js 静态导出，通过 GitHub Actions 发布到 GitHub Pages。
- GitHub Pages 部署必须同时支持默认仓库子路径和自定义域名根路径。

## 6. 首版不包含

- 登录、账号、自建留言后台和云端计算记录
- 数据库、后台和行业趋势面板
- 自动抓取平台费率
- ERP、店铺或广告平台 API
- 自动汇率换算、税务申报或会计建议

## 7. 验收标准

- 通用模式不选择平台和分类也能完成计算。
- 平台切换后分类列表与费率参考同步更新。
- 盈利、亏损、全零和费率达到 100% 等场景均有稳定结果。
- 目标售价重新带入正向公式后，利润率与目标值在一分钱误差内闭环。
- 首屏直接进入计算器，默认参数不超过一个主工作区。
- 计算输入不会被发送到应用服务器或分析服务。
- 联系页只提供邮箱入口，不显示在线留言表单，也不发送站内请求。
- GitHub Pages 默认仓库子路径和自定义域名根路径构建均通过，全部公开路由和资源可访问。
- 平台指南在 320px 屏幕上不依赖横向滚动，并支持键盘筛选、展开和候选管理。
- Lint、类型检查、自动化测试和生产构建全部通过。

## 8. 后续方向

后续变更可以增加用户主动触发的匿名提交、SQLite 存储和聚合趋势分析。分析结果必须标记为“计算器用户样本”，并记录费率来自预设还是用户修改，避免把预设数据误当成真实行业观测。
