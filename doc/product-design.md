# 电商利润计算器产品与技术设计

> 版本：1.5
> 更新日期：2026-10-04

## 1. 设计命题

页面不是营销落地页，而是一张“利润仪表”。用户进入后立即看到订单输入与经营结果，视觉重心放在数值判断，不使用大面积装饰、渐变或复杂动效。

目标体验是“轻输入，重结果”：默认区只保留平台、分类和四个核心金额；专业参数收进一个高级设置区；结果端完整呈现利润、效率、定价和广告边界。

## 2. 信息架构

```text
全站导航
└── 电商利润计算器
    ├── 页面标题与本地计算提示
    ├── 订单参数
    │   ├── 平台 / 分类 / 人民币范围
    │   ├── 四个核心金额
    │   └── 高级设置
    │       ├── 快速估算 / 专业核算
    │       ├── 按经营任务渐进展示字段
    │       └── 费率来源与模板复核状态
    ├── 经营结果
    │   ├── 决策就绪状态与订单贡献利润
    │   ├── 贡献利润率 / 订单成本回报 / 月度预测
    │   ├── 专业结算明细（按需）
    │   ├── 核算完整度与建议确认项
    │   ├── 单笔贡献刻度
    │   ├── 定价与广告边界
    │   └── 成本构成
    ├── 固定广告区域
    └── 计算口径摘要
```

平台对比页是第二个核心工作面：经营路径地图 → 筛选后的平台列表 → 最多三个候选对比 → 新手选择顺序。辅助页面包括联系、计算口径、隐私政策和使用条款。

## 3. 响应式布局

桌面端：

```text
┌──────────────────────────────────────────────┐
│ 标题                                  本地计算 │
├────────────────────┬─────────────────────────┤
│ 订单参数            │ 利润信号                 │
│ 平台 / 分类 / 币种   │ 利润率 / ROI / 月利润     │
│ 核心金额            │ 贡献刻度                 │
│ 高级设置            │ 定价边界 / 成本构成       │
└────────────────────┴─────────────────────────┘
```

移动端：标题、短表单、折叠的高级设置、结果、广告和口径内容依次排列。高级设置默认折叠，因此不会把结果推到很远的位置。

专业核算在 540px 以下将费用规则和任务分组改为单列；模式控件始终保持两段等宽。长平台字段名允许换行，但不得推动输入控件超出工作面。

平台对比页在桌面端使用对齐的决策列，移动端改为“适合、不太适合、成本结构”标签化纵向事实，不使用需要横向拖动的宽表格。

## 4. 视觉系统

- 矿物白 `#F4F7F5`：页面背景
- 纸白 `#FFFFFF`：工具工作面
- 碳黑 `#17201C`：主文本和成本刻度
- 账本青绿 `#087F6D`：盈利与正向状态
- 信号琥珀 `#D99524`：提醒与广告成本
- 损失珊瑚 `#C94F45`：亏损与风险
- 数据靛蓝 `#4059AD`：选择、目标和链接

中文正文使用系统无衬线字体，金额和百分比使用等宽数字字体。圆角限制在 4-6px，结构依靠分隔线而不是卡片嵌套。

标志性元素是“单笔贡献刻度”：一条固定高度的水平刻度将收入、成本和剩余利润放在同一尺度；亏损时刻度切换为损失色并显示超支金额。

平台对比页的标志性元素是“经营路径地图”：从商家的经营起点分叉到五类经营方式，筛选结果数量与说明同步变化。它编码真实选择路径，不作为纯装饰。

联系页使用一条清晰的公开联络线：直接展示邮箱、邮件入口和敏感信息提醒，以账本式分隔线承接全站视觉，不放置尚不可用的输入控件。

## 5. 交互设计

- 所有结果随输入即时更新，不需要“开始计算”按钮。
- 高级设置内使用两段式控件切换快速估算和专业核算；默认始终为快速估算。
- 专业字段按收入、交易费用、售后和月度规划排列，不使用嵌套装饰卡片。
- 平台模板切换字段词汇和建议计费基数，不自动填入未经核验的数字费率。
- 达人佣金字段只在达人/分销渠道显示，隐藏时保留输入但不参与利润计算。
- 平台切换后，分类重置为通用类目并应用平台通用参考。
- 分类存在专属预设时应用分类费率；不存在时显示平台通用回退状态。
- 用户编辑平台费、支付费或退款预留后显示手工调整状态。
- 需要后台或合同费率的平台先显示琥珀色预览状态；用户明确确认当前平台与支付费用后，才显示正常盈利、亏损或持平状态。
- 平台、分类或平台及支付费用发生变化时清除原确认，退款预留等经营假设的变化不要求重复确认平台费用。
- 核算完整度只用于提示常见零值成本区域，不阻断计算，也不把合法的零成本判为错误。
- 国内版固定人民币 CNY，不提供仅改变符号的伪汇率切换。
- 数字字段允许编辑时暂时留空，失焦后再归零。
- 重置使用图标按钮，并提供标题与无障碍名称。
- 不可反推的费率组合显示具体原因，不输出 `NaN` 或误导性的零值。
- 专业模式使用有边界的数值求解复用正向模型；存在无法分摊的月成本时，反推指标显示不可用。
- 无法公开核验的国内平台费率显示“待核对”，0 不得被表达为免佣。
- 平台对比页按经营路径筛选，候选上限为三个；优劣与近期信号按平台展开。
- 客户可见文案只描述经营动作、费用判断和当前隐私承诺，不展示数据库、接口或样本分析等内部规划。
- 联系页的邮箱链接只打开用户设备上的邮件应用，不读取计算器状态。

## 6. 技术边界

应用使用 Next.js App Router、React 和严格 TypeScript。利润公式位于纯函数模块，预设与平台指南位于版本化数据模块，客户端组件只维护表单、筛选和候选状态。

当前没有自建应用 API、数据库或第三方表单端点。联系页只提供 `mailto:` 邮箱链接。未来计算数据提交流程采用独立仓储边界，服务器必须重新验证输入并重算结果，不能直接信任浏览器提交的派生字段。

项目始终使用 Next.js 静态导出，通过 GitHub Actions 发布到 GitHub Pages。默认项目地址从公开 URL 生成 `/mini-tools` 路径；绑定自定义域名后自动使用域名根路径。

## 7. 可访问性与性能

- 表单控件拥有显式标签、键盘焦点和足够对比度。
- 动态结果区域使用温和的 `aria-live`，避免频繁打断。
- 系统请求减少动态效果时停用过渡。
- 结果区使用稳定网格和固定广告高度，避免数值与广告加载造成布局跳动。
- 首版不加载外部字体、图表库、状态库或广告脚本。
